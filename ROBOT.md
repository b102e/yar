# YAR и тело

Ветка `robot-body`: YAR получает физическое тело — маленького робота с камерой, головой,
глазами-дисплеями, голосом и гусеницами. Код тела — в отдельном проекте `claude-body`.

```
            дом (NAT)                                    VPS 24/7
┌──────────────────────────────┐          ┌──────────────────────────────────┐
│ робот (Pi Zero 2W)           │   wss    │ YAR: identity · chain · brain    │
│  body_client.py ─────────────┼─────────►│  embodiment/link.py  (сервер)    │
│  лимиты, питание, стоп       │◄─────────┼─ embodiment/turn.py  (tool use)  │
│  офлайн-режим                │  команды │  Telegram bridge                 │
└──────────────────────────────┘          └──────────────────────────────────┘
```

Робот сам подключается к YAR (исходящее соединение), поэтому ему не нужен белый IP,
а YAR не знает адреса дома.

## Что изменилось в YAR

| Файл | Что |
|---|---|
| `embodiment/link.py` | WebSocket-сервер для тела: токен, heartbeat, статус, команды с таймаутами |
| `embodiment/tools.py` | инструменты `body_*` для Claude; набор зависит от связи, заряда и стопа |
| `embodiment/turn.py` | цикл tool use: действие → результат → следующее действие |
| `brain/agent.py` | `attach_body()`; телесный ход, если тело на связи; блок «ТЕЛО» в промпте; `feel` → глаза; события тела в цепочку; вызовы Claude в потоке (не держат event loop) |
| `brain/telegram_bridge.py` | события тела владельцу; ответы, уже прозвучавшие голосом, не дублируются; `/die` останавливает тело навсегда |
| `main.py` | поднимает BodyLink, если задан `BODY_TOKEN` |

Без `BODY_TOKEN` YAR работает ровно как раньше.

## Правила, которые держатся в коде

- **Сам по себе Яр не ездит.** Автономные мысли не получают телесных инструментов.
  Движение — только в ответ человеку. `autonomy_level` на права тела не влияет.
- **Лимиты — на теле.** Расстояние, скорость, таймаут моторов, блокировка при низком
  заряде и аварийный стоп решает робот. YAR их видит, но не может обойти.
- **Аварийный стоп снимает только человек** — голосом («можно ехать») или кнопкой.
- **Нет связи — тело стоит.** Обрыв прерывает текущее движение; тело говорит, что связи
  нет, и переподключается само. Яр в это время знает, сколько он уже без тела, и не
  обещает физических действий.
- **Заряд.** Робот шлёт заряд каждые 5 с. `low` (≤25%) — короткие отрезки, Яр может
  попросить зарядку; `critical` (≤10%) — моторы заблокированы, остаются взгляд, глаза и
  голос; `shutdown` (≤3%) — робот предупреждает и выключается. Зарядку Яр тоже видит.
- **Смерть.** `/die` переводит тело в неподвижное состояние навсегда, глаза гаснут.
  Новое тело можно привязать только к новому генезису.

События тела (`connected`, `disconnected`, `battery_level`, `charging`, `estop`,
`shutdown`) пишутся в подписанную цепочку с типом `body`. Владелец получает в Telegram
только важные: потеря связи, низкий и критический заряд, стоп, выключение.

## Развёртывание

1. В `.env` YAR:
   ```
   BODY_TOKEN=<python -c "import secrets; print(secrets.token_urlsafe(32))">
   BODY_HOST=127.0.0.1
   BODY_PORT=8765
   ```
   `pip install -r requirements.txt` (добавлен `websockets`), перезапустить `yar.service`.

2. TLS снаружи — через reverse proxy. Пример для Caddy (сертификат получит сам):
   ```
   yar.example.com {
       handle /body* {
           reverse_proxy 127.0.0.1:8765
       }
   }
   ```
   Порт 8765 наружу не открывать.

3. На роботе:
   ```
   export BODY_TOKEN=<тот же>
   export YAR_URL=wss://yar.example.com/body
   ROBOT_MODE=pi python body_client.py
   ```

## Проверено

Сквозной тест в симуляции (настоящий агент YAR, BodyLink и тело на localhost, Claude
подменён сценарием) — 35 проверок: подключение, голосовой ход с кадром и движением,
урезание лимитов, текст из Telegram без кадра, low / critical / зарядка, голосовой стоп
во время движения, обрыв связи с обеих сторон и переподключение, смерть субъекта,
валидность цепочки после всего.

Не проверено: с настоящим Claude API, на железе, через Caddy.
`lifecycle/test_die.py` падал и до этих изменений (содержимое записей теперь шифруется,
а тест читает его как dict).
